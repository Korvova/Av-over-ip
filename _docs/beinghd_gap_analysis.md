# BeingHD JSON API — анализ совместимости с платформой RMS

> ОБНОВЛЕНИЕ (ответ завода, 2026-08-11, серия IPX; по IPB — отдельное приложение):
> 1. Discovery — ЕСТЬ: multicast 239.1.0.0:8804, `{"cmd":"discovery","msgtype":0}` (формат ответа уточнить на демо-ките)
> 2. Версия ПО — ЕСТЬ: UDP 6004, `{"cmd":"getsoftversion"}`; отдельной команды типа устройства нет — проверить, есть ли тип в ответе discovery
> 3. HTTP-превью — НЕ ПОДДЕРЖИВАЕТСЯ → транскодируем RTSP→MJPEG на контроллере (ffmpeg, превью-поток rtsp ch0/2 720x576@15 лёгкий)
> 4. CEC — только модуль 4K60 (учитывать при заказе железа)
> 5. USB-матрица — только кастомная прошивка (несовместима со стандартной); частичный обход: setselectwindow (USB следует за выбранным окном)
> 6. EDID, 7. LED панели, 10. ИК 5В, 11. HDCP, 12. Вкл/выкл выхода — только кастомная прошивка (несовместима со стандартной)
> 8. Поворот — только у всей стены целиком, не отдельных панелей
> 9. Компенсация рамок — ПОДДЕРЖИВАЕТСЯ ✅
> Демо-кит IPX получен — тестировать discovery/getsoftversion и формат ответов.
> СТРАТЕГИЧЕСКИЙ ВОПРОС к заводу: собрать ВСЕ кастомизации (5,6,7,10,11,12) в одну прошивку «RMS edition»? Сроки/стоимость/поддержка обновлений.

Источник: «JSON Control Protocol BeingHD.xlsx» (114 команд, JSON по UDP:6004 / TCP:6006 /
multicast 239.1.0.1:8804; потоки RTSP :8554).

Парадигма отличается от ASPEED: декодер «открывает окна» и сам тянет RTSP/multicast-потоки
по URL. Это даже мощнее (мозаика окон, поверх/вниз, сцены в устройствах), но управляется иначе —
нужен отдельный драйвер `beinghd.js` (архитектура платформы это уже позволяет: слой drivers/).

| Разрешение выхода | setvoattr (+нестандартные тайминги setvouersync — бонус для LED) |

## КРИТИЧНЫЕ ПРОБЕЛЫ ❌ — просить завод добавить

1. **Discovery (обнаружение устройств)** — главный пробел. В API нет команды «найти все
   устройства в сети»: управлять можно, только заранее зная IP. Нужно: broadcast/multicast-запрос,
   на который каждое устройство отвечает: тип (TX/RX), MAC, IP, ID, версия ПО.
   (У ASPEED это node_query, у самих BeingHD наверняка есть в их ПО — нужен протокол.)
2. **Тип устройства и версия прошивки** — нет команды `getdevicetype` / `getversion`.
   Платформа должна отличать энкодер от декодера и показывать прошивку (ТЗ, стр. «Элементы системы»).
3. **HTTP-превью (JPEG snapshot / MJPEG)** — есть только RTSP (rtsp://ip:8554/ch0/2),
   браузеры RTSP не играют. Нужен HTTP-эндпоинт `GET /snapshot.jpg` и/или MJPEG-поток.
   Иначе контроллер обязан транскодировать RTSP→MJPEG (ffmpeg, нагрузка на CPU контроллера).
4. **CEC over IP** — команд нет вообще, а ТЗ требует независимую маршрутизацию CEC.
5. **USB/KVM маршрутизация явной командой** — сейчас USB следует за «выбранным окном»
   (setselectwindow). Нужна прямая команда «USB декодера → энкодер X» для матрицы USB из ТЗ.

## ЖЕЛАТЕЛЬНЫЕ ПРОБЕЛЫ ⚠️ (для полноты ТЗ)

6. EDID: выбор из предустановок / чтение EDID дисплея декодера / запись пользовательского (ТЗ: 27 вариантов + 2 ячейки).
7. LED-индикаторы передней панели: Вкл / Вкл 60 сек / Выкл (ТЗ).
8. Поворот/переворот изображения декодера: 0/90/180/270/гориз./верт. (ТЗ) — нет.
9. Компенсация рамок LCD-стен: в newwall есть размеры панелей, но нет явных полей
   «внешний/видимый размер» — уточнить у завода методику.
10. ИК-порт: выбор напряжения 5В/12В (ТЗ) — нет.
11. HDCP-режимы (совместимость с защищённым контентом) — нет.
12. Вкл/выкл видеовыхода декодера отдельной командой (ТЗ) — сейчас только closewindow/backcolor.

## Вопросы на уточнение

- setio/getio помечены «Board Changes — this command is no longer meaningful» — чем заменено?
- getdhcp «GK hardware version does not support» — какие версии железа поддерживают DHCP?
- Максимумы: количество устройств, стен, окон на декодер.
- Формат «серверного IP» (serverip в setnet) — что за сервер, обязателен ли.

## Вывод

Ядро платформы (коммутация видео/аудио, видеостены, сеть, сцены, RS-232/ИК, реле) на этом API
реализуемо уже сейчас. Для продукта по ТЗ заводу нужно добавить пункты 1–5 (критичные),
пункты 6–12 — по возможности. Пункты 1–3 — обязательные: без discovery и типа устройства
не работает автоматический поиск из мастера настройки, без HTTP-превью — живые миниатюры
в интерфейсе.
