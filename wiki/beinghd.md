Второй производитель, устройства серий IPX и IPB. Рассматривается как альтернативная
аппаратная база для той же платформы. Управление устроено иначе, чем у ASPEED:
JSON-команды по UDP (порт 6004), групповой адрес 239.1.0.1:8804, потоки RTSP.
Декодер не «подписывается на канал», а открывает окна и сам тянет потоки по адресу —
это позволяет мозаику из нескольких источников на одном экране.

Поддержка сводится к написанию третьего драйвера рядом с существующими, платформу
менять не требуется.

## Что уже закрыто их API

Коммутация видео и аудио (аудио — отдельно, с регулировкой громкости), видеостены
с панелями разного разрешения и компенсацией рамок, мозаика окон, сетевые настройки,
RS-232 и ИК, реле и порты IO, перезагрузка и два вида сброса, время работы и загрузка
процессора, экранные надписи, сцены прямо в устройствах, яркость и контраст,
параметры кодирования.

## Чего не хватает — ответы завода

| Требование | Ответ завода |
|---|---|
| Поиск устройств | Есть: групповой адрес 239.1.0.1:8804, команда `{"cmd":"discovery","msgtype":0}` |
| Версия прошивки | Есть: `{"cmd":"getsoftversion"}` на адрес устройства, порт 6004 |
| Тип устройства | Команды нет: узлы умеют и кодировать, и декодировать |
| Живая картинка по HTTP | Не поддерживается — только RTSP |
| CEC | Только на модулях 4K60 |
| USB-матрица | Кастомная прошивка, и только клавиатура с мышью |
| EDID, светодиоды, ИК 5В, HDCP, вкл/выкл выхода | Кастомная прошивка, завод согласен сделать |
| Поворот изображения | Только для всей стены целиком, не для отдельной панели |
| Компенсация рамок | Поддерживается |

Кастомная прошивка несовместима со стандартной — значит, все доработки имеет смысл
собирать в одну сборку, а не заказывать по частям.

## Известный формат ответа

```
{"cmd":"getsoftversion","msgtype":1,"code":0,"msg":"OK.",
 "hardversion":"K400MC-71G","version":"2.2.0.28","buildtime":"2026-05-18 10:04:40"}
```

Поле `hardversion` — модель железа. Похоже, именно оно решает вопрос с типом узла:
если у энкодера и декодера строки моделей разные, роль определяется по ним и никаких
новых команд от завода не нужно.

## Открытые вопросы к заводу

1. Формат **ответа** на discovery — присылают команду, а нужен лог ответа устройства,
   как это сделано для `getsoftversion`.
2. Строки `hardversion` у энкодера и у декодера — если различаются, вопрос роли закрыт.
3. Набор CEC-команд для модуля 4K60.
4. Список команд серии IPB — вложение до нас не дошло.

## Отсутствие HTTP-картинки

Веб-интерфейс показывает живые миниатюры всех источников, а браузеры RTSP не играют.
Значит, контроллер будет перекодировать их лёгкий превью-поток (720×576, 15 кадров)
в MJPEG силами ffmpeg. Нагрузка ложится на мини-ПК, поэтому перекодировать имеет
смысл только те миниатюры, которые сейчас видны на экране.

## Инструменты

`tools/beinghd_probe.js` — утилита разведки протокола: слушает групповой адрес,
отправляет discovery, снимает полный портрет устройства по известному IP. Написана,
чтобы получить форматы ответов самостоятельно, не дожидаясь завода.

```
node beinghd_probe.js listen <ip-интерфейса>     слушать шину
node beinghd_probe.js discover <ip-интерфейса>   послать discovery и собрать ответы
node beinghd_probe.js scan <ip-устройства>       полный портрет устройства
```
